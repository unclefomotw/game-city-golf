## 設計原則：為反覆試玩而設計

Spec 有很多項目要「實際遊玩後逐步決定」（SHOT-2、SHOT-4、LVL-4、第 4 節 POC 範圍），所以實作上要遵守：

- **可調參數集中管理**：手感相關的數值放在一個設定物件，開發模式下可以用調參面板即時修改，調好後匯出成預設值。
- **可替換的策略**：瞄準操作方式、旋轉效應公式、相機控制方式都寫成可替換的模組，換方案時不必改到其他部分。
- **POC 的取捨不寫死**：例如「單關」做成「關卡清單只有一筆」；「沒有音效」做成「有事件可以接，只是還沒有接上聲音」。但只保留擴充的接縫，不先做出用不到的功能。

## 實作方向

### 場地（FLD-1、FLD-2）

- 場地是一個長方體，四面牆與天花板是不可破壞的邊界。牆可以畫成半透明或只畫邊框，避免擋住視線。
- 終點範圍用醒目的發光柱或旗幟標示，從遠處也看得到。
- 完成判定：球被判定為停止時，球心位於終點範圍內才算完成（PLAY-4）。飛行或滾動途中經過範圍不觸發。

### 建築與破壞（DES-2 ~ DES-7）

- 每棟建築是一個 3D 格子，每格是一個單位方塊，整棟用 `InstancedMesh` 一次畫出來。
- 球撞到建築時，刪除撞擊點周圍半徑內的格子，在建築上挖出洞（DES-2、DES-3）。挖洞半徑可以和撞擊速度相關。
- 碰撞判斷直接查詢格子有沒有被佔用，所以洞挖出來後球可以穿過（DES-4）。
- 被刪除的格子轉成碎塊粒子，用假重力、旋轉、縮小的方式飛散後消失。碎塊不參與碰撞（DES-5、DES-6），數量設上限以照顧手機效能。
- 破壞分數在 POC 等於被刪除的方塊數量（DES-7）。計分寫成獨立函式，輸入是一次破壞事件（方塊數、所屬建築等），之後要改計分方式只需換掉這個函式。
- 選配：失去支撐的懸空方塊整塊掉落。

### 球的運動模型（SHOT-3、SHOT-4、PLAY-3）

以固定時間步長（暫定 1/120 秒）推進，同一組輸入一定得到同樣的結果。每一步的加速度由下列項目相加，每一項都是可以單獨開關、替換的函式：

| 項目 | 暫定公式 | 參數 |
|---|---|---|
| 重力 | `g` 朝下 | `gravity` |
| 旋轉效應 | 類 Magnus 力：`k · (ω × v)` | `magnusK` |
| 旋轉衰減 | `ω ← ω · e^(−λ·dt)` | `spinDecay` |
| 空氣阻力 | 線性：`−c · v`（比平方阻力更容易預期） | `airDrag` |

旋轉以向量 `ω` 表示，由玩家指定的兩個分量組成：
- **左右旋**：繞垂直軸旋轉。叉積 `ω × v` 產生側向力，讓球路彎曲。
- **上下旋**：繞「水平且垂直於初速」的軸旋轉。下旋產生向上的升力（飛得更遠、更平），上旋讓球往下壓。

選擇類 Magnus 力的理由：旋轉效應自然取決於「當下的速度與方向」，球越快彎得越明顯，球越慢效應越小，看起來合理又可預期。旋轉衰減讓效應隨時間減弱。這兩項加起來，就涵蓋了使用者提到的「初速向量、當下方向、當下速度、經過時間」幾種因素。如果試玩後覺得不好控制，可以換成更簡單的「固定側向加速度、隨時間衰減」模型。

**碰撞與接觸**（地面、建築、場地邊界）：
- 反彈：法向速度乘以反彈係數 `e`，地面、建築、邊界各自有不同的係數。
- 摩擦：切向速度乘以摩擦係數。
- 旋轉與接觸互動：落地時，上旋增加前進速度（落地後往前衝），下旋減少前進速度（落地後煞車，甚至往回滾）。
- 滾動：貼地時套用滾動摩擦；速度低於門檻並持續一小段時間就判定為停止。

### 瞄準與擊球（SHOT-1 ~ SHOT-3）（暫定）

- 將 2D 操作轉換成 3D 方向：
  - **方案 A：彈弓式（第一個試做版本）**。在正方形畫面上從球往外拖曳，反向就是發射方向。左右拖曳決定相對於相機的水平方向，上下拖曳決定仰角，拖曳長度決定力道。
  - **方案 B：相機即方向**。相機面對的方向就是水平方向，再用拖曳或滑桿決定仰角與力道。
- **3D 方向的視覺回饋**：
  - 從球伸出一支 3D 箭頭，長度代表力道。
  - 在地面畫出箭頭的投影線，同時顯示一條垂直的仰角弧線，讓玩家同時看清楚水平方向與仰角。
  - 預覽軌跡（SHOT-5）：用同一套物理模擬往前推算一小段時間（參數 `previewSeconds`，可調），畫成虛線。物理是確定性的，所以預覽的這一段和實際結果一致。
  - 預覽遇到地面或建築時照常計算反彈，繼續畫出撞擊後的走向。撞到建築時，實際擊球會挖洞並影響後續路徑，所以預覽也要模擬破壞：在真實格子之上疊一層「預覽中被刪除的格子」暫存集合，碰撞查詢同時參考兩者，預覽結束就丟棄，不改動真實場景。
- **旋轉的指定**：在控制面板放一個「球面」元件，玩家點選或拖曳擊球點（類似撞球遊戲的加塞介面）。偏左或偏右是左右旋，偏上或偏下是上下旋。
- **罰桿**（PLAY-5、PLAY-6）：控制面板固定放一顆「罰桿・回上一位」按鈕，任何時候都可以按，包括球還在飛行或滾動時。按下後桿數加 1，球回到上一桿的擊球位置；建築破壞維持原狀。

### 視角（CAM-1、CAM-2）（暫定）

分成兩種模式：

- **擊球模式**：相機繞著球轉（orbit）。拖曳畫面空白處旋轉視角，滾輪或雙指捏合縮放。
- **靈魂出竅模式**：自由飛行。
  - 桌機：WASD 移動，Q/E 上下，按住右鍵或用 pointer lock 轉視角，Shift 加速。
  - 手機：在**正方形以外的控制區放一個虛擬搖桿**負責移動，旁邊放上下按鈕。在正方形畫面內單指拖曳轉視角，雙指捏合前進或後退。這是手機 3D 遊戲常見的「左移動、右轉向」雙搖桿配置；搖桿放在畫面外，手指就不會擋住場景。
  - 提供「回到球」按鈕（CAM-2）。
  - 選配：俯瞰全圖按鈕，點地圖上任一點就飛過去。

### 畫面配置（UI-1、UI-2）

- 主 canvas 固定 1:1（CSS `aspect-ratio`），用 `@media (orientation)` 切換版面：橫向時控制面板在右側，直向時在下方。
- 限制 `devicePixelRatio` 上限、只開一盞投影光源，以中階手機為效能基準。

### 關卡生成（LVL-1 ~ LVL-4）

- 使用帶 seed 的偽亂數產生器，同一個 seed 會產生同一張地圖（LVL-2）。
- 生成城市網格（道路、街區、不同高度的建築），再放置起點與終點範圍。
- 檢查起點到終點之間存在可行路線，不可行就換下一個 seed 重新生成（LVL-3）。
- 一局由「關卡清單」驅動，POC 的清單只有一關（LVL-4）。

### 開發與驗收（ACC-1）

- 開發時執行 `vite --host`，手機連同一個 Wi-Fi 就能開啟遊玩。
- 推送到 main 後自動部署到 GitHub Pages，使用者有固定網址可以驗收。
- 遊戲畫面顯示目前地圖的 seed，方便使用者回報問題。
- 網址加上 `?debug` 會開啟調參面板，試玩時可以即時調整手感。
