```
  core/rng.ts          帶 seed 的亂數（LVL-2）

  world/levelGen.ts    城市生成與可完成性檢查（LVL-1 ~ LVL-3）
  world/testScenes.ts  開發者測試場景（預先定義，只在開發模式出現，ADR-010）
  physics/ballSim.ts   球的運動、碰撞、挖洞、預覽軌跡（純邏輯）
  game/game.ts         桿數、罰桿、完成判定的狀態機（純邏輯）
  game/scoring.ts      破壞分數規則（DES-7）
  render/              Three.js：場景、建築網格、碎塊、瞄準視覺、相機
  input/viewInput.ts   正方形畫面上的指標（轉視角、縮放）與鍵盤輸入
  input/aimStick.ts    方向搖桿的偏移→轉速換算與仰角限制（純邏輯，ADR-013）
  input/inputKind.ts   判斷玩家正在用滑鼠鍵盤還是觸控，決定操作提示（ADR-012）
  ui/widgets.ts        旋轉球面、搖桿、長按按鈕
  debug/tuning.ts      ?debug 調參面板
test/logic.test.ts     純邏輯測試，測試名稱標註對應的 spec ID
```

純邏輯（`core`、`world`、`physics`、`game`）不依賴 DOM 和渲染，可以在 Node 直接測試。`three` 在這些模組裡只用來做向量運算。

## 設計原則：為反覆試玩而設計

Spec 有很多項目要「實際遊玩後逐步決定」（SHOT-2、SHOT-4、LVL-4、第 4 節 POC 範圍），所以實作上要遵守：

- **可調參數集中管理**：手感相關的數值都在 `config.ts`。網址加 `?debug` 會出現調參面板，可以即時修改，調好後按「匯出設定」複製 JSON，再更新預設值。
- **可替換的策略**：瞄準操作方式、旋轉效應公式、相機控制方式各自獨立，換方案時不必改到其他部分。
- **POC 的取捨不寫死**，但只保留接縫，不先做出用不到的功能：
  - 單關：`Game` 只負責一關。之後要做多關，在外面包一層管理多個 `Game` 即可。
  - 沒有音效：物理模擬已經會產生 `bounce` 和 `destroy` 事件，之後接上聲音即可。

## 實作細節

### 場地（FLD-1、FLD-2）

- 場地是 72 × 40 × 72 格的長方體。四面牆與天花板是不可破壞的邊界，只畫出邊框，不擋視線。場地外圍鋪一大片草地，避免看到虛空。
- 終點是地面上的圓形範圍，用發光的半透明光柱、地面圓環和旗子標示，從遠處也看得到。
- 完成判定（PLAY-4）：球停止時，球心位於終點圓內，而且貼在地面（`y < 1`），才算完成。飛行或滾動途中經過不會觸發。

### 建築與破壞（DES-2 ~ DES-7）

- 每格是 1 單位的方塊，格子值是「建築 id + 1」，0 表示空格。
- 渲染：只畫至少有一面暴露在外的格子，整個城市用一個 `InstancedMesh` 畫出來。格子有變動時整個重建；重建只在發生破壞時才做，成本可以接受。
- 挖洞：球撞到建築時，如果撞擊速度超過 `minSpeed`，就刪除撞擊點周圍半徑 `min(maxRadius, 速度 × radiusPerSpeed)` 內的格子。
- 打穿或反彈：挖完洞後重新檢查碰撞。如果已經不再碰到建築，球就穿過去，速度按刪除的格子數衰減（每格乘 `speedKeptPerCell`）；如果還碰得到，就照常反彈。這樣一套規則就同時產生「輕打會彈開、重打會打穿」的效果（DES-4）。
- 碎塊（DES-5、DES-6）：每個被刪除的格子變成兩個碎塊，帶著原建築的顏色從撞擊點往外飛散，受假重力影響、會旋轉和縮小，1.4 秒後消失。碎塊總數有上限，滿了就覆蓋最舊的。破壞時鏡頭會震動，畫面上方顯示「破壞 +N」。
- 破壞分數（DES-7）：POC 每格 1 分，規則在 `game/scoring.ts`。

### 球的運動模型（SHOT-3、SHOT-4、PLAY-3）

以固定時間步長（1/120 秒）推進，同一組輸入一定得到同樣的結果。每一步再細分成子步，確保球每個子步移動不超過半徑的一半，避免高速時穿牆。

| 項目 | 公式 | 參數 |
|---|---|---|
| 重力 | `g` 朝下 | `gravity` |
| 旋轉效應 | 類 Magnus 力：`k · (ω × v)`，只在空中作用 | `magnusK` |
| 旋轉衰減 | `ω ← ω · e^(−λ·dt)` | `spinDecay` |
| 空氣阻力 | 線性：`−c · v` | `airDrag` |

旋轉向量 `ω` 由兩個分量組成：

- **左右旋**：繞垂直軸。`ω × v` 產生側向力，讓球路彎曲。
- **上下旋**：繞「水平且垂直於擊球方向」的軸。下旋產生升力，上旋讓球往下壓。

**碰撞與接觸**（地面、建築、場地邊界）：

- 法向速度大於 `rollThreshold` 時是**反彈**：法向速度乘以反彈係數，切向速度乘以摩擦係數，再加上旋轉造成的切向速度 `contactSpinK · (ω × n)`。上旋讓球落地後往前衝，下旋讓球煞車。每次反彈後旋轉保留 `contactSpinRetain`。
- 法向速度小於門檻時是**滾動**：法向速度歸零，剩下的旋轉逐漸轉成滾動速度，同時套用滾動摩擦。
- 速度低於 `stopSpeed` 並持續 `stopTime` 秒，就判定為停止。

目前預設值大約是：力道 60%、仰角 30°，飛行約 27 格、總距離約 44 格；滿力道約可飛 71 格。

### 瞄準與擊球（SHOT-1 ~ SHOT-3）（暫定）

目前採用**方向搖桿**（ADR-013，取代 ADR-008 的彈弓式）：

- 控制面板上的方向搖桿以**速率控制**調整擊球方向：搖桿偏移決定角度「轉動的速度」，不是角度本身。
  - 左右：轉動水平方向。往右推，方向往右轉（從上方看順時針）。
  - 上下：調整仰角。**往上推（遠離自己）仰角變大**，往下拉仰角變小，就像「把準星往上抬」。
  - 推得越遠轉得越快；放開後搖桿彈回中心，角度停在當下的位置。
  - 轉速：滿偏移時水平 `aim.azimuthRateDeg`（預設 90°/s）、仰角 `aim.elevationRateDeg`（預設 60°/s）。中心有死區 `aim.stickDeadZone`，偏移量經過反應曲線 `t^aim.stickExponent`（預設 2），中心附近轉得很慢，方便微調。這些參數都可以在 `?debug` 調參面板的「方向搖桿」即時調整。
  - 仰角限制在 `aim.minElevationDeg` ~ `aim.maxElevationDeg`（−45° ~ 89°），水平方向沒有限制，可以轉一整圈（SHOT-1）。
  - 換算邏輯是純函式 `input/aimStick.ts`（`stickResponse`、`stepAim`），有單元測試。
- 桌機也可以用**方向鍵**：←→ 轉水平方向、↑↓ 調仰角，相當於把搖桿推到 `aim.keyboardDeflection`（預設 0.6）。方向鍵只在擊球模式有效，不和靈魂出竅的 WASD/QE 衝突。拖曳完力道滑桿後會自動取消焦點，讓方向鍵回到瞄準。
- 搖桿下方顯示目前的方向（相對於終點方向，例如「右 12°」）與仰角。
- 在正方形畫面上拖曳**只會旋轉視角**（滾輪或雙指捏合拉近／拉遠），不再設定擊球。
- 力道用面板上的水平滑桿設定。調好之後按「擊球」才會發射。
- **3D 方向的視覺回饋**：
  - 從球伸出一支 3D 箭頭，指向發射方向，長度和顏色（綠到紅）代表力道。
  - 地面上畫出箭頭的投影線，表示水平方向；球旁邊畫一條弧線，表示仰角。
  - 預覽軌跡（SHOT-5）：用同一套物理模擬往前推算 `preview.seconds`（預設 0.6 秒），畫成一串白點。點的間距越大代表速度越快。預覽遇到地面或建築會照常反彈或挖洞，挖洞只記在 `PreviewOverlay` 暫存，不改動真實場景。
- **旋轉**：面板上的「球面」元件，點選擊球點就像撞球的加塞。左右是側旋，上是上旋，下是下旋；點在中心附近會自動歸零。
- **罰桿**（PLAY-5、PLAY-6）：任何時候都可以按，包括球還在飛行時。按下後桿數加 1，球回到上一桿的位置，建築破壞維持原狀。

### 視角（CAM-1、CAM-2）（暫定）

- **擊球模式**：相機繞著球轉。在畫面空白處拖曳可以旋轉視角，滾輪或雙指捏合可以拉近／拉遠。球飛行時相機會平滑跟隨。
  - 建築擋住視線時，相機會自動往上抬，越過屋頂看到球，而不是拉近貼到球上。
  - 如果怎麼抬都看不到（例如球停在打出來的隧道裡），相機就維持原本的距離，讓球、瞄準箭頭和預覽以「透視」方式畫在建築前面。
- **靈魂出竅模式**：自由飛行。
  - 前進／後退沿著視線方向，包含上下：往下看再前進就會下降（ADR-011）。左右平移維持水平，升降按鍵則是純垂直移動，可以在不改變視線的情況下升降。
  - 桌機：WASD 移動，Q/E 下降和上升，Shift 加速，拖曳畫面轉視角，滾輪拉近／拉遠（相機沿視線方向移動，不是改變視野角度）。
  - 手機：用正方形外控制區的虛擬搖桿移動，旁邊有上升和下降按鈕；在畫面內單指拖曳轉視角，雙指捏合拉近／拉遠。
  - 可以飛到場地外 10 格以內，避免迷路。
  - 「回到球」按鈕切回擊球模式（CAM-2）。

### 畫面配置（UI-1、UI-2）

- `main.ts` 依視窗大小計算正方形的邊長：橫向時是 `min(高, 寬 − 280px)`，控制面板放在右側；直向時是 `min(寬, 高 − 240px)`，控制面板放在下方。面板內容太長時可以捲動。
- 面板由上到下是：地圖代號、桿數、破壞分數 → 擊球設定 → 擊球鈕 → 罰桿、靈魂出竅、新地圖 → 操作提示。
- 擊球設定是同一列，由左到右：**方向搖桿**（下方顯示方向與仰角）｜**力道滑桿**（水平）｜**旋轉球面**（ADR-013）。
  - 橫向：面板寬度至少 280px，左右內距 12px，可用 256px。搖桿 78px、旋轉球面 76px、間距 8px，力道滑桿至少有 86px。
  - 直向：面板是整個螢幕寬，搖桿放大到 100px、旋轉球面 92px，力道滑桿最寬 180px 並置中。寬 320px 的手機上力道滑桿約 80px。
  - 尺寸用 `#aim-controls` 上的 CSS 變數 `--stick-size`、`--spin-size` 設定，依 `orientation` 切換。
- 靈魂出竅模式不能擊球，所以擊球設定這一區和擊球鈕都會隱藏，改顯示飛行控制。兩個搖桿是不同的元件，同一時間只會出現一個；搖桿在拖曳中被隱藏時會自動回到中心。
- 操作提示只寫玩家正在用的那一套操作（滑鼠鍵盤或觸控）。一開始依主要指標裝置猜測，之後跟著最後一次實際輸入切換（ADR-012）。控制項本身不分裝置，都會顯示。
- 效能：`devicePixelRatio` 上限 2，只有一盞投影光源。

### 關卡生成（LVL-1 ~ LVL-4）

- 地圖代號就是 seed，放在網址 `?seed=` 裡。開啟時沒有帶 seed 會隨機產生一個並寫回網址（LVL-2）。
- 生成方式是在 XZ 平面上散放長方形建築，允許重疊；不切街區，也沒有路網（ADR-016）。步驟：
  1. 起點固定在 (1.5, 1.5) 角落（`TEE`）。起點中心在 x、z 方向 `TEE_CLEARANCE`（5 格）內是保留區（地格 0 ~ 6），最近的建築面距離起點中心 5.5 格。
  2. 終點從「離起點 ≥ 最遠可能距離的 75%」的位置中隨機挑一個，半徑 3 格，周圍 8 × 8 格是保留區（終點廣場）。目前地圖大小下，終點離起點約 70 ~ 94 格。
  3. 隨機散放長方形（每邊 3 ~ 12 格），直到覆蓋 `COVERAGE`（30%）的地面。長方形可以超出邊界再裁掉，所以邊緣和中間被蓋到的機率一樣。和保留區重疊的部分會被裁掉，保留最大的一塊。
  4. 逐列、逐欄檢查直線空地。只要有一段超過 `MAX_OPEN_RUN`（36 格），就在它的中段再放一個小長方形（每邊 3 ~ 5 格），重複直到沒有為止。所以**沒有任何直線空地能從邊界的一端通到另一端**。這一步讓覆蓋率最後大約落在 40%（最多約 47%），空地約六成。
  5. 每個長方形是一棟建築，高度通常 4 ~ 14 格，有 20% 的機率是 18 ~ 30 格的高樓。重疊的地方就是兩棟合在一起。
- 可完成性（LVL-3）：檢查起點到終點之間有一條地面高度的通道。生成失敗時在同一個亂數序列裡重試，確保同一個 seed 一定得到同一張地圖。

### 開發與驗收（ACC-1）

- `npm run dev` 會帶 `--host` 啟動，手機連同一個 Wi-Fi，開啟終端機顯示的 Network 網址即可試玩。
- 「新地圖」會換一個 seed 並重新載入；完成畫面可以選「再玩這張地圖」。

### 開發者測試場景（ADR-010）

給開發者觀察擊球手感用的預先定義場景，不是遊戲內容，玩家不會碰到。

- 開啟方式：網址帶 `?scene=<id>`，或在面板最下方的「測試場景」下拉選單挑選（選了會重新載入）。選「無」回到隨機城市；按「新地圖」也會離開測試場景。
- 只在開發模式（`npm run dev`）有效。正式 build 裡 `import.meta.env.DEV` 為 false，`?scene=` 會被忽略，選單不會出現，場景程式碼也會被 tree-shake 掉。一般玩法的隨機 seed 一律走 `generateLevel`，不可能抽到測試場景。
- 新增場景：在 `src/world/testScenes.ts` 的 `TEST_SCENES` 加一筆 `{ id, label, build }`，`build` 回傳一個 `Level`。測試會自動檢查每個場景都能完成。
- 目前的場景：

| id | 內容 | 用途 |
|---|---|---|
| `empty` | 場地大小與正式關卡相同，沒有任何建築。起點在角落 (4.5, 4.5)，終點在對角。地上以起點為圓心，每 10 格畫一圈淺色距離環。 | 專心觀察擊球操作、實際球路、力道與距離的關係 |

## 已知限制

- 建築的格子在每次破壞後會整個重建。目前的地圖大小沒有問題，但地圖再放大時可能要改成分區更新。
- 被打穿的方塊上方不會因為失去支撐而掉落，懸空方塊是允許的（DES-3 允許粗糙的結果）。
