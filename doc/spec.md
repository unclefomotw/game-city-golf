# City Golf — 產品規格（Spec）

> 本文件只描述 **WHY + WHAT**，與實作方式無關。規則見 `AGENTS.md`。
> 來源：`doc/IDEATION.md`，以及使用者在 2026-10-16 的補充回答。
>
> **標記說明**：沒有標記的條目是使用者明確提出的需求。`〔提案〕` 是 agent 推論出的條目，尚待使用者確認，確認後移除標記。

## 1. 為什麼（WHY）

- 把高爾夫「一桿一桿規劃路線」的策略感，和「把城市打爛」的破壞快感結合在一起。
- 城市既是障礙，也是可以被改變的地形。玩家的每一桿不只是推進球，也在改寫後面的路線。
- 隨開即玩：打開網頁就能玩，桌機和手機都可以。

## 2. 產品概述

單人網頁遊戲。玩家在一個非擬真的 3D 城市中，像打高爾夫一樣，把球從起點一回合一回合打到終點。每一桿由玩家決定擊球的力道、角度和旋轉。球打到建築物時會破壞建築物，場景因此持久改變。

## 3. 需求（WHAT）

### 3.1 平台

| ID | 需求 |
|---|---|
| PLT-1 | 在網頁瀏覽器上遊玩，不需要安裝。 |
| PLT-2 | 單人遊戲。 |
| PLT-3 | 支援桌機與手機。桌機用滑鼠操作，手機用觸控操作，兩者都能完整遊玩。 |

### 3.2 核心玩法

| ID | 需求 |
|---|---|
| PLAY-1 | 球從起點出發，以回合制推進，每回合打一桿，直到球抵達終點。 |
| PLAY-2 | 每一桿由玩家指定擊球的**力道**、**角度**、**旋轉**。 |
| PLAY-3 | 球的行為不需要擬真，但必須**可預期、可學習**：相同的擊球設定會得到相近的結果，玩家能逐漸掌握手感。 |
| PLAY-4 | 球**停在終點範圍內**即完成關卡，並顯示這一關總共用了幾桿。球只是飛越或滾過終點範圍、沒有停在裡面，不算完成。 |
| PLAY-5 | 玩家在任何時候都可以選擇**罰桿**：桿數加 1，球回到上一桿的擊球位置。這同時涵蓋了球卡住、或停在不想打的位置等情況。 |
| PLAY-6 | 罰桿只讓球回到原位，已經造成的建築破壞不會復原（與 DES-2 一致）。 |

### 3.3 擊球：角度與旋轉

| ID | 需求 |
|---|---|
| SHOT-1 | 擊球方向是 3D 全方位的：玩家可以同時指定**水平方向**與**仰角**，沒有死角。 |
| SHOT-2 | 玩家實際上是在 2D 螢幕上操作，因此發射前必須有清楚的視覺回饋，讓玩家看得出球會往 3D 空間中的哪個方向出發，對結果有正確的期待。具體的操作方式（例如反向拖曳的彈弓式、正向拖曳，或其他方式）透過實際遊玩反覆驗證後決定。 |
| SHOT-3 | 旋轉包含兩種，並且都由玩家指定：**左右旋**讓球路側向彎曲；**上下旋**影響球的飛行，以及落地後的彈跳與滾動。 |
| SHOT-4 | 球的運動受到以下影響：擊球的初速（方向與力道）、重力、旋轉造成的偏移、空氣阻力、與地面和建築之間的摩擦，以及撞到地面和建築時的反彈。各項影響的具體形式與強弱，透過實際遊玩反覆調整。 |
| SHOT-5 | 發射前的預覽只顯示**出發方向與一小段飛行軌跡**，不顯示完整路徑或落點。如果這一小段軌跡會撞到任何東西（地面、建築或場地邊界），預覽在撞擊點截斷，不顯示撞擊之後的走向，讓玩家無法靠預覽判斷反彈。 |

### 3.4 場地

| ID | 需求 |
|---|---|
| FLD-1 | 整個場地位在一個長方體空間內。長方體的邊界無法被破壞，球不可能離開場地，因此沒有「出界」。 |
| FLD-2 | 終點是場地中的一個範圍，玩家要能清楚辨識它的位置。 |

### 3.5 場景與破壞

| ID | 需求 |
|---|---|
| DES-1 | 場景是一座非擬真的 3D 城市。 |
| DES-2 | 球打到建築物時可以破壞建築物，場景因玩家的互動而改變，而且改變會保留到這一關結束。 |
| DES-3 | 破壞的結果可以粗糙，例如建築被挖掉幾塊方塊、留下一個洞。 |
| DES-4 | 被破壞後的建築形狀會影響之後的球路，例如球可以穿過被打出來的洞。 |
| DES-5 | 破壞建築要有動畫效果。 |
| DES-6 | 破壞時飛散的碎塊只是視覺效果，不會影響球。 |
| DES-7 | 破壞建築會累積專屬的**破壞分數**，並顯示給玩家。計分方式與如何納入遊戲機制，透過試玩調整（POC 做法見第 4 節）。 |

### 3.6 視覺風格

| ID | 需求 |
|---|---|
| VIS-1 | 粗糙風格，例如城市裡的建築物由長方體構成。 |
| VIS-2 | 球的運動與破壞動畫不需要擬真、不需要符合真實物理，重點是表現感。 |

### 3.7 畫面與操作

| ID | 需求 |
|---|---|
| UI-1 | 主場景畫面為 1:1 正方形。 |
| UI-2 | 不論螢幕是直向或橫向，正方形以外的空間用來放操控按鈕、設定和資訊。 |
| UI-3 | 所有操作（擊球設定、擊球、觀看場景等）都能用滑鼠完成，也都能用觸控完成。 |

### 3.8 視角

| ID | 需求 |
|---|---|
| CAM-1 | 玩家可以進入「靈魂出竅」模式：視角離開球，在場地中自由移動、自由轉向，瀏覽整個場地。桌機與手機都要能操作。 |
| CAM-2 | 玩家可以一鍵從「靈魂出竅」回到球所在的位置，準備擊球。 |

### 3.9 關卡與一局的組成

| ID | 需求 |
|---|---|
| LVL-1 | 關卡由程式自動生成，不需要手工設計，也不需要關卡編輯器。 |
| LVL-2 | 每一張生成的地圖都有一個代號，用同一個代號可以重新產生同一張地圖，方便回報問題或重玩。 |
| LVL-3 | 生成的關卡一定能夠完成。 |
| LVL-4 | 一局由單關或多關組成，尚未決定，會在實際遊玩驗證後逐步決定。 |

### 3.10 驗收

| ID | 需求 |
|---|---|
| ACC-1 | 由使用者實際遊玩來驗收。 |

## 4. 第一版 POC 範圍

下列是**第一版 POC 的取捨，不是長期限制**。之後會透過實際遊玩驗證，逐步決定要不要擴充。

| 項目 | POC 的做法 | 之後 |
|---|---|---|
| 一局的組成（LVL-4） | 單關 | 可能擴充為多關 |
| 音效與音樂 | 不做 | 可能加入 |
| 桿數上限、標準桿、星等評分 | 不做 | 之後再考慮，因為牽涉到如何依場地判斷難度 |
| 破壞分數（DES-7） | 依被破壞的方塊數量計分，只累積並顯示 | 試玩後調整計分方式，並決定如何整合進遊戲機制 |

## 5. 非目標（明確不做）

- 擬真的物理模擬
- 擬真或精緻的畫面
- 多人或連線對戰
- 手工關卡與關卡編輯器
